# Cloudflare clef: API and probe (2026-10-06)

Question: can Cloudflare's `clef` model stand in for Jev behind go-decide, and
what would that cost in code?

Run the probe with `go test -tags probe -run TestClefDecisions -v -count=1`
(`clef_probe_test.go`). It needs `CLOUDFLARE_ACCOUNT_ID` and
`CLOUDFLARE_AUTH_TOKEN` in the environment or the ignored `.env`, and it
spends a small amount of Workers AI quota (about 7.5 neurons per call).

## API shape

`POST https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/run/@cf/cloudflare/clef`
with `Authorization: Bearer $CLOUDFLARE_AUTH_TOKEN`.

| | System One (`api.typesafe.ai`) | clef (Cloudflare) |
| --- | --- | --- |
| Endpoint | `POST /v1/systemone` | `POST /client/v4/accounts/{id}/ai/run/@cf/cloudflare/clef` |
| Request body | `state`, `questions`, optional `model` | `model`, `state`, `questions`; all three required |
| Question types | `noul`, `choice`, `score` | the same three, same fields |
| Response | `answers`, `usage` at the top level | wrapped: `result.{model,answers,usage}`, `success`, `errors`, `messages` |
| Answer objects | `noul`, `choice`, `score`, `probabilities`, `confidence` | the same, plus `legend` on a score |
| Cost signal | `usage.input_tokens` | `usage.input_tokens` and a `cf-ai-neurons` header |
| Errors | TypeSafe codes, listed in `docs/jev-errors.md` | Cloudflare `errors[].code` and message, for example 5006 for bad input |

A missing `model` is rejected with code 5006, so unlike Jev there is no default.
One call took 0.69 s.

## Probe results

The same 40 decisions and three questions as
`docs/spike-decisions-2026-09-29.md`.

| Model | Dominant correct | Mean confidence, dominant | Mean confidence, contested | AUC from 1 minus confidence | AUC from entropy |
| --- | --- | --- | --- | --- | --- |
| clef | 20 of 20 | 0.96 | 0.56 | 0.93 | 0.91 |
| Jev | 20 of 20 | 0.98 | 0.58 | 0.98 | 0.97 |

Jev's figures moved by 0.01 between two runs, as identical Jev calls vary
slightly; clef's came from a cached run. Reversing the option order changed
clef's pick on 0 of 20 dominant and 4 of 20 contested decisions. Jev changed on
0 and 2.

Reading it:

- Both models solve the constraint-checking decisions. The same caveats as the
  Jev spike apply: synthetic data, n of 40, a favourable test.
- clef's confidence is a usable gate but a weaker one. The separation is
  about the same in mean, with a wider overlap, so the placeholder thresholds
  (0.9 and 0.5) cannot be shared between models. Thresholds need tuning per
  model (issue #6).
- clef is less stable on contested decisions, which is where stability
  matters. One run, so treat the 4 against 2 as a hint, not a result.
- Confidence and top probability are different numbers. The example call
  gave a `technical` probability of 0.81 with a confidence
  of 0.53.

## Findings that shape a backend

- The two wire formats differ only in the endpoint, the `model` field, the
  auth credential and the response envelope. The question and answer objects
  are the same, so `decision` and `eval` need no change.
- `kataras/jev` builds its request body with a private encoder
  (`encoding/json/v2` hooks), so `jev.Questions` cannot be marshalled
  from outside the package. `json.Marshal` emits Go field names and Cloudflare
  answers with code 5006.
- A `jev.Client` can still talk to Cloudflare. The probe gives it Cloudflare's
  host as the base URL and a `RoundTripper` that rewrites the path to the clef
  run path and replaces the response body with `result`. That keeps jev's
  request encoding and answer validation, at the price of depending on how jev
  forms its path and envelope.
- `jevclient.Classify` maps TypeSafe failures. Cloudflare failures need their own
  mapping to `contract.Error` codes. Only one failure has been seen so far: an
  HTTP 400 with `success: false` and code 5006. Auth, rate-limit and server
  failures still need to be provoked and recorded.
- `CONTEXT.md` forbids third-party gateways and any non-TypeSafe endpoint.
  Cloudflare is a first-party host of the model, not a proxy, but the rule
  needs an explicit amendment before code lands.

## Reusing the adaptation from another client

A project that already has a System One client does not need `clefclient`'s
client. `clefclient` exports the two pieces that adapt Cloudflare:

```go
// .../client/v4/accounts/<id>/ai/run/@cf/cloudflare on api.cloudflare.com
base, err := clefclient.BaseURL(accountID)
httpClient := &http.Client{
    Transport: clefclient.NewTransport(nil),
    CheckRedirect: func(*http.Request, []*http.Request) error {
        return http.ErrUseLastResponse
    },
}
// Point the client at base, use httpClient, send the Cloudflare token as the
// bearer token, and put "model": "clef" in every request body.
```

The transport swaps `/v1/systemone` for the clef run path and unwraps the
`result` envelope, so the client sees a flat System One response and a path
that is not a base URL swap becomes one. It refuses every other path (so
`GET /v1/models` has no clef equivalent), holds no token, and does not retry:
429 handling and refusing redirects stay with the caller's client.

Importing `github.com/rshade/go-decide/clefclient` from another module needs
Go 1.27.1 and pulls in `kataras/jev`, `ax-go` and `golang.org/x/time`. A
module outside this repository was built against it with a `replace`
directive. There is no tagged release yet, so use a pseudo-version or a
`replace` until v0.1.0.

`clefclient/testdata/response.json` is a real recorded response with a noul, a
choice and a score answer, for tests that must not hand-write a fixture.
